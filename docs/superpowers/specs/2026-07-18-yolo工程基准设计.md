# YOLO 工程基准设计

## 1. 目标与边界

YOLO 是视频分析系统的低成本感知前端，负责定位人物、过滤无效帧，并为后续 ByteTrack、VLM、RAG 和 Agent 提供结构化输入。本阶段不训练模型、不制作人工标注集，也不计算本项目 Precision、Recall 或 mAP。

## 2. 模型方案

- 使用 Ultralytics 官方 COCO 预训练权重。
- `YOLOv8s` 为默认模型，`YOLOv8n` 为轻量性能对照。
- 只保留 COCO class id `0`（`person`）。
- 首轮统一 `imgsz=640`、`batch=1`、相同置信度和 IoU 阈值。
- GPU 可用时使用 FP16；CPU 环境自动关闭 FP16 并明确记录，禁止伪装成 GPU 结果。

## 3. 模块边界

- `ai/yolo_detector.py`：模型生命周期、单帧推理、行人过滤、结构化输出。
- `ai/benchmark.py`：分位数、吞吐量、资源与视频级统计，不负责加载具体模型。
- `scripts/benchmark_yolo.py`：命令行编排、视频读取、预热、输出 JSON/图片/视频。
- `tests/test_yolo_detector.py`：使用伪后端测试业务逻辑，不下载模型。
- `tests/test_yolo_benchmark.py`：测试指标聚合、边界输入和序列化。

## 4. 数据结构

单个检测框包含 `class_id`、`class_name`、`confidence`、`xyxy`。单帧结果包含帧序号、视频时间戳、图像尺寸、检测框列表，以及 `preprocess_ms`、`inference_ms`、`postprocess_ms`、`total_ms`。

基准摘要包含模型、设备、精度模式、输入尺寸、视频信息、处理帧数、检测总数、平均 FPS、各阶段平均值与端到端 P50/P95/P99、进程内存和 GPU 显存峰值。所有时间统一使用毫秒，FPS 使用帧/秒。

## 5. 测试策略

- 单元测试：模型后端注入，覆盖只保留行人、空检测、非法帧、FP16 设备约束和指标分位数。
- 集成测试：真实权重和现有 `data/videos/test_45s.mp4`，先短片段冒烟，再完整 45 秒。
- 性能测试：每个模型先预热，再重复同样帧范围；首次推理单独记录，避免混入稳定态延迟。
- 定性检查：按固定间隔保存检测图，人工查看 20～30 张，不输出精度百分比。

## 6. 错误与降级

- 权重不存在时允许 Ultralytics 下载；下载失败时输出明确错误和目标路径。
- 视频打不开、首帧为空、输出目录不可写时快速失败，不生成虚假空报告。
- 请求 CUDA 但不可用时默认报错；只有显式指定 `--device cpu` 才允许 CPU 基准。
- 报告记录实际设备与 FP16 状态，防止配置值与真实运行状态不一致。

## 7. 后续衔接

检测器输出保持与模型实现解耦，下一阶段可以接入 ByteTrack。跟踪后的目标事件再进入 Redis，VLM 根据关键帧、区域、停留时间和队列压力进行调度，避免逐帧调用大模型。
