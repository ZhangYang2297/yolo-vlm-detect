## 2. 测试目标与范围

### 2.1 本轮目标

1. 验证配置能从 YAML 与环境变量正确加载。
2. 验证数据库模型、关系、默认值、JSON 字段和分页。
3. 验证 Redis 队列、缓存 TTL、Pub/Sub 和并发入队。
4. 验证 MinIO 建桶、上传、对象检查和并发上传。
5. 验证任务与告警 API 的正常、异常和边界行为。
6. 验证真实 TCP HTTP 服务可访问并建立本机响应基线。
7. 验证 Docker 基础服务的存活状态和端口连通性。

### 2.2 不在本轮范围

- YOLO 模型加载、精度、召回率、推理延迟与显存。
- VLM 请求、重试、缓存、Prompt、Token 成本和降级。
- 音频抽取、VAD、ASR、异常声音分类。
- RTSP 实际发布、HLS/WebRTC 播放、弱网和断流重连。
- ChromaDB 文档解析、向量检索和规则召回率。
- 登录鉴权、RBAC、限流、CSRF、防重放及完整渗透测试。

## 9. 基础攻击输入测试

### 9.1 已验证输入

| 攻击类型 | 输入示例 | 当前结果 | 正确解读 |
|---|---|---|---|
| SQL 注入 | `' OR '1'='1`、`DROP TABLE` 字符串 | 作为普通值保存，表未被破坏 | ORM 参数化降低了该路径的注入风险 |
| XSS | `<script>alert('xss')</script>` | JSON 中原样返回 | 只证明存储/API 不执行脚本，不证明页面安全 |
| 路径遍历 | `../../etc/passwd` | 当前作为字符串保存 | 不能视为已防护，媒体读取前必须校验 |
| 非法 JSON | 截断 JSON / garbage | 返回 400 | 通过 |

### 9.2 已确认安全缺口

1. 模板中的部分数据通过 JavaScript `innerHTML` 拼接，任务名、告警标题、描述或 VLM 原文若来自恶意输入，浏览器页面仍可能发生存储型 XSS。生产前应改用 `textContent`、DOM API 或统一 HTML 转义库，并增加浏览器级 XSS 测试。
2. `source_url` 目前不读取资源，所以路径遍历和 SSRF 字符串“被接受”不等于安全。后续 OpenCV/FFmpeg 拉流前必须限制 `http/https/rtsp` 协议、拒绝环回/链路本地/内网地址、限制本地根目录、检查 DNS 重绑定与重定向。
3. 当前 `CORS(app)` 全开放，无鉴权、RBAC、CSRF 和限流，绝不能直接暴露公网。
4. Docker Compose 与 `.env.example` 中存在开发默认口令。开发可用，生产必须改成随机强密码并使用 secret 管理。

## 13. 缺陷发现、修复与复测

### D-01 Prometheus 重复注册

- **现象**：测试多次调用 `create_app()` 时，同名 Prometheus 指标重复注册。
- **根因**：Prometheus 默认 Registry 是进程级全局对象，每个 Flask app 都再次注册。
- **修复**：`create_app(register_metrics=True)` 增加开关，并用全局 `_metrics` 保证只注册一次；测试 app 使用 `False`。
- **复测**：多次创建测试 app，全量 52 项通过，`/metrics` 可访问。
- **经验**：应用工厂可重复创建不代表第三方全局 Registry 可重复初始化。

### D-02 API 非法输入处理不足

- **现象**：空请求、非 JSON、缺少名称/视频源、非法复核状态缺少一致的客户端错误响应。
- **根因**：初版接口直接读取字段并写数据库，缺少入口校验。
- **修复**：使用 `request.get_json(silent=True)`，补必填校验、长度限制、状态白名单和分页上限。
- **复测**：异常、边界和安全输入用例全部通过。
- **经验**：校验必须发生在系统边界；当前手写校验后续应升级为 Pydantic 请求模型。

### D-03 Redis TTL 写入

- **现象**：缓存过期行为需要明确且原子。
- **根因**：设置值和过期时间若拆成两步，进程中断可能留下永久键。
- **修复**：使用 `SET key value EX ttl`，代码为 `r.set(..., ex=ttl)`。
- **复测**：写入后立即命中，等待 2 秒后 1 秒 TTL 键返回 `None`。
- **经验**：能用 Redis 单条原子命令完成时，不拆成多条命令。

### D-04 XSS 测试受历史数据污染

- **现象**：安全用例偶发失败，但并非脚本执行或业务值被修改。
- **根因**：测试按同名记录数量断言，真实开发库残留同名数据。
- **修复**：按创建 API 返回的主键精确查询，并在 fixture 清理测试名称。
- **复测**：安全专项 5/5、全量 52/52 通过。
- **经验**：测试必须拥有自己的数据标识，不能假设共享数据库为空。

### D-05 测试文件出现字面量 `\n`

- **现象**：`tests/test_api.py` 产生 Python 语法错误。
- **根因**：PowerShell 字符串替换把换行写成了两个普通字符 `\` 与 `n`。
- **修复**：恢复正常多行源码，并使用标准补丁机制修改文件。
- **复测**：测试收集恢复正常，全量通过。
- **经验**：自动改源码后要先做语法/收集检查，再判断业务失败。

## 14. 已知风险与准入判断

| 风险 | 级别 | 当前处理 |
|---|---|---|
| 页面动态 HTML 可能导致存储型 XSS | 高 | 已识别，尚未修复 |

| 开发默认密码与全开放 CORS | 中高 | 生产配置必须整改 |
| MinIO 签名 URL 默认 7 天 | 中 | 按敏感度缩短并审计 |
| SQLAlchemy 旧 API warning | 低 | 后续升级 |
| 测试使用共享开发基础设施 | 中 | CI 使用隔离环境 |

准入判断：**允许进入阶段二开发；不允许以当前形态对公网或真实生产数据开放。**
