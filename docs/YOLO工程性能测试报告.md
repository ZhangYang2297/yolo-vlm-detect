# YOLO 工程性能测试报告

> 测试日期：2026-07-18  
> 测试范围：YOLOv8n 与 YOLOv8s 的 CPU 工程性能和抽样定性检查  
> 重要边界：本报告不包含人工标注、Precision、Recall、mAP，不代表模型精度评测

## 1. 测试目的

本阶段把 YOLO 作为视频分析系统的低成本感知入口，只验证以下问题：

1. 模型能否加载并稳定处理完整视频。
2. 预处理、模型推理、后处理和端到端延迟分别是多少。
3. YOLOv8n 与 YOLOv8s 在同一台机器、同一视频和同一参数下的性能差异。
4. 抽样图片中是否能够看到有效的行人检测框。
5. 当前 CPU 能力能否满足 25 FPS 原速视频的实时处理要求。

检测数量只能反映两个模型在当前阈值下输出框数量不同，不能直接解释为准确率、召回率或漏检率。

## 4. 测试过程

### 4.1 权重校验

- `model_weights/yolov8n.pt` 和 `model_weights/yolov8s.pt` 均能被 Ultralytics 正常加载。
- YOLOv8s 权重大小为 `22,588,772` bytes，约 21.5 MiB。

### 4.2 冒烟测试

YOLOv8s 先处理 20 帧，确认模型、视频解码、检测、统计、JSON 和抽样图片链路正常：

- 处理帧数：20
- 实际吞吐：`7.05 FPS`
- 端到端 P95：`138.21 ms`
- 检测框数量：305
- 峰值进程内存：`547.35 MiB`

### 4.3 完整视频测试

两个模型都使用完全相同的参数处理全部 1127 帧，原始 JSON 保存在：

- `data/benchmark/yolov8n-cpu-full/benchmark.json`
- `data/benchmark/yolov8s-cpu-full/benchmark.json`

## 5. 完整基准结果

| 指标 | YOLOv8n | YOLOv8s | 说明 |
|---|---:|---:|---|
| 成功处理帧数 | 1127 | 1127 | 两个模型均完整处理视频 |
| 总检测框数 | 11834 | 13762 | v8s 多 16.29%，不等同于更准确 |
| 实际吞吐 | 12.93 FPS | 7.68 FPS | v8s 比 v8n 低 40.63% |
| 推理平均延迟 | 66.09 ms | 119.15 ms | 模型核心推理时间 |
| 端到端平均延迟 | 70.83 ms | 123.75 ms | 包含检测调用外围开销 |
| 端到端 P50 | 60.09 ms | 121.89 ms | 中位延迟 |
| 端到端 P95 | 96.20 ms | 136.17 ms | v8s 比 v8n 高 41.55% |
| 端到端 P99 | 103.26 ms | 156.39 ms | 尾延迟 |
| 峰值进程内存 | 511.96 MiB | 561.67 MiB | v8s 多 49.71 MiB |

模型加载和冷启动只发生在进程启动阶段，受磁盘缓存、Python 进程状态等因素影响较大。本轮 v8n 先运行、v8s 后运行，所以不能根据单次加载数据判断 v8s 加载更快；稳定吞吐和正式处理阶段延迟更有参考价值。

## 6. 结果分析

### 6.1 实时性

原视频是 25 FPS：

- YOLOv8n 的处理能力约为原速的 `51.72%`。
- YOLOv8s 的处理能力约为原速的 `30.71%`。

因此，在当前 CPU、每帧检测、`imgsz=640` 的配置下，两个模型都不能实时处理该视频。若只要求离线分析，两者均可正常运行；若要求实时处理，需要 GPU、抽帧、跟踪复用、动态调度或更小输入尺寸。

### 6.2 模型选择

- CPU 开发和链路联调优先使用 YOLOv8n，反馈更快、资源成本更低。
- GPU 恢复后，再用相同参数比较 YOLOv8n 与 YOLOv8s；默认业务模型是否使用 v8s，应同时考虑后续场景中的定性效果和 VLM 触发成本。
- v8s 输出框更多，只能说明它在当前视频和阈值下更积极地输出候选，不能据此声称漏检更少。

### 6.3 后续系统优化方向

1. 使用 ByteTrack 等跟踪器维持目标轨迹，不必每帧都执行完整检测。
2. 按固定间隔或场景变化动态抽帧，把检测吞吐与视频帧率解耦。
3. 只在新目标、轨迹状态变化或规则命中时调用 VLM，避免逐帧调用大模型。
4. GPU 恢复后测试 CUDA FP16，再评估 ONNX Runtime 或 TensorRT；不同后端必须使用相同输入和统计口径。
5. 将视频读取、推理和结果写入拆成有界队列，监控队列长度并设置背压，避免积压导致内存持续增长。

## 7. 抽样定性检查

已检查完整基准中的多张抽样图片，能够看到近处、远处和部分遮挡行人的检测框，说明视频解码、坐标转换、类别过滤和绘制链路有效。

该检查只能回答“链路是否输出看起来合理的结果”，不能回答 Precision、Recall、小目标召回率等问题。后者必须依赖人工标注或可信公开标注数据集。

## 8. 当前结论

1. YOLO 行人检测工程链路已经实现并可处理完整视频。
2. 当前 CPU 基线下，YOLOv8n 更适合作为日常开发和联调模型。
3. 当前每帧检测无法达到 25 FPS 实时要求，后续必须使用 GPU或降低检测频率。
4. GPU 性能测试因本机显卡故障暂缓，修复驱动和设备状态后使用同一脚本补测。
5. 本阶段没有精度标签，不应在简历或面试中宣称完成 Precision、Recall 或 mAP 评测。

## 9. 复现命令

```powershell
python scripts/benchmark_yolo.py `
  --source data/videos/test_45s.mp4 `
  --output-dir data/benchmark/yolov8s-cpu-full `
  --model model_weights/yolov8s.pt `
  --device cpu `
  --no-half `
  --image-size 640 `
  --warmup-frames 3 `
  --sample-every 100
```

GPU 恢复后，不应直接沿用本轮结论。应固定视频、阈值、输入尺寸、预热帧数和抽帧策略，分别运行 CUDA FP32 与 FP16，再更新本报告。
