## 1. 推荐阅读顺序

如果你是第一次接触本项目，建议按下面顺序学习：

1. [选择性对齐设计](superpowers/specs/2026-07-18-参考系统选择性对齐设计.md)：先理解哪些参考系统设计被采用、改良、后置或放弃。
2. [AI视频分析系统总实施路线图](superpowers/plans/2026-07-18-AI视频分析系统总实施路线图.md)：理解完整目标架构、阶段依赖、接口和发布门禁。
3. [集中式 YOLO 与 Tracker 实施计划](superpowers/plans/2026-07-19-集中式YOLO与Tracker实施计划.md)：查看当前阶段的纵向切片、接口、页面与测试步骤。
4. [实施计划](实施计划.md)：查看面向项目学习和进度管理的阶段总览。
5. [模块开发详解](模块开发详解.md)：理解每个模块为什么存在、如何实现、怎样交互。
6. [项目知识手册](项目知识手册.md)：补齐 Docker、Python、数据库、并发、AI、安全和测试知识。
7. [阶段一测试报告](阶段一测试报告.md)：了解系统怎样验证、发现过什么问题、当前有哪些风险。
8. [MediaMTX视频链路测试报告](MediaMTX视频链路测试报告.md)：查看真实推拉流、缺陷定位、协议验证和剩余风险。
9. [YOLO工程性能测试报告](YOLO工程性能测试报告.md)：查看 YOLOv8n/v8s 的 CPU 延迟、吞吐、资源和选型结论。
10. [AI视频数据分析系统说明文档](AI视频数据分析系统说明文档.md)：仅作为外部项目思路参考，不代表当前仓库已经实现。

学习时不要只阅读结论。建议一边看“模块开发详解”，一边打开对应代码；遇到不懂的概念，再去“项目知识手册”查原理和命令。

| Capture Worker 与原始预览 | 已实现 | 支持本地文件/RTSP 拉流、有界缓冲、背压、状态 API、MJPEG 调试页和停止释放 |
| 集中式 Inference Worker | 已实现 | 共享一个 YOLO、公平消费最新帧，输出检测画面、分阶段耗时、推理 FPS 和 P95 |
| 多目标跟踪 | 已实现 | 基于 IoU 的轻量跟踪器，支持 TENTATIVE/CONFIRMED/LOST 状态、轨迹线和 track_id 可视化 |
| VLM 行为理解 | 后续设计 | 尚无调用、结构化输出、重试、缓存和降级实现 |
| 音频分析 | 后续设计 | 尚无音频抽取、VAD、声音事件检测或多模态融合实现 |
| Capture/Inference/Event Producer/VLM Consumer/Saver | 后续设计 | 尚未形成基于 Redis Streams 的完整异步 AI 告警链路 |
| RAG 规则增强 | 后续设计 | 尚未接入 ChromaDB、文档解析和检索评测 |
| 公网生产部署 | 未达到 | 鉴权、RBAC、限流、CSRF、CORS 白名单、SSRF 防护等仍需完成 |

状态含义：

- **已实现**：当前仓库有代码，并通过阶段一测试。
- **部分实现**：基础设施或骨架存在，但核心业务链路没有验收。
- **后续设计**：文档给出了方案，当前仓库还没有实现。
- **未达到**：不能把当前版本直接作为公网生产系统发布。

## 5. 参考文档与当前实现的区别

`AI视频数据分析系统说明文档.md` 描述的是别人已经完成的系统，主要用于学习产品形态和架构思路。本文档中的 Producer、Consumer、Saver、YOLO、VLM、RAG、热更新等内容，不应直接当作本仓库已经具备的能力。

本项目开发和面试陈述必须以当前代码、测试报告和本页状态矩阵为准。更稳妥的表达是：

> 我参考成熟系统完成了选择性架构对齐，已独立搭建基础设施、视频源与任务控制面，并打通 RTSP/OpenCV/HLS、Capture Worker 和共享 YOLO 实时检测链路。当前全量自动化为 202 项，真实 1080p CPU 冒烟可输出带框画面和分阶段指标；下一步接入 Tracker、ROI 与候选去重，再进入 Redis Streams、VLM、RAG 和告警闭环。

## 6. 面试准备方法

1. 能在三分钟内讲清业务场景、痛点、总体架构和当前完成边界。
2. 能解释为什么 MySQL、Redis、MinIO、MediaMTX 各自不可互相替代。
3. 能沿着一次请求和一次未来告警，讲清数据如何流动。
4. 能解释 Redis List 当前的可靠性不足，以及 ACK、重试、幂等和死信队列的改进方案。
5. 能说明 YOLO 与 VLM 的分工、为什么不能每帧都调用 VLM，以及如何在 RTX 4050 上控制显存和延迟。
6. 能复述至少两个真实缺陷的发现、定位、修复和复测过程。
7. 诚实区分“已经实现”“已经设计”“准备开发”，不要把参考系统包装为自己的完成成果。
